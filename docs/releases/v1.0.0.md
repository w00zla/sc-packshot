The first release of packshot: bulk renders of Star Citizen items from your own copy of the game, on one PC or a
cluster of PCs, driven from a terminal UI.

## What it does

- **Bulk:** exports thousands of entities from `Data.p4k` with [starbreaker-ps](https://github.com/w00zla/starbreaker-ps)
  (a StarBreaker fork) and renders them in Blender, with long-lived export and Blender processes fed one job at a time.
- **One PC or a cluster:** nodes find each other on the LAN; any node can start a run, files move by content hash.
- **The game's own staging:** pose and light rig per item type from the game's inventory data, including the entries
  tied to an entity's tags (pistols get the sidearms rig).
- **Profiles:** the look is a profile, a folder with `profile.toml` and four Python hooks; the bundled `game-tile`
  mimics the game's inventory tiles. A profile can bring its own copy of the StarBreaker add-on or a scene `.blend`.
- **Sets with a fixed output:** every set renders at its own size and format (PNG, JPEG or linear EXR), fixed when the
  set is created; runs are kept as they were, sets pick the newest image per entity, experiments branch off `main`.
- **Measured, not guessed:** an assessment finds how many processes a node carries (one entry per operating system).

## Install

1. Download the bundle for your OS below and unpack it anywhere.
2. Run `setup.cmd` (Windows) or `bash setup.sh` (Linux): it downloads the pinned Blender (5.2.3) from blender.org,
   checks its SHA256 and enables the add-on.
3. Run `check.cmd` / `bash check.sh` (does Eevee render on Vulkan here?), then `run.cmd --render --export` /
   `./run.sh --render --export`. Exports need `Data.p4k` with its `build_manifest.id` next to it (`--p4k <path>`,
   `SC_DATA_P4K`, or a `Data.p4k` in the bundle folder).

The bundles carry packshot, StarBreaker 0.3.2-ps.5 with its Blender add-on, `render.py` and the `game-tile` profile.
Check the downloads against `SHA256SUMS`. Details: the [README](https://github.com/w00zla/sc-packshot#readme).

## Known limits

- A cluster run across several real machines has been tested only with two nodes on one machine so far.
- The Windows bundle's `setup.cmd` has not been run on a second machine yet; please report what breaks.
- Nodes run Python they receive (`render.py`, profiles); share a cluster only with machines and people you trust.
