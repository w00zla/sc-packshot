A small release: clearer names in the terminal UI. The images are the same as with 1.0.0.

## What changed

- **The default profile is called `default`:** the bundled profile that mimics the game's inventory tiles was
  `game-tile`; it is now `profiles/default/`, and `--profile default` chooses it. The name is reserved: an own profile
  called `default` is refused, and no node can send one under that name. Its look is unchanged.
- **Labels:** the default profile shows no origin any more ("bundled" is gone); other profiles still say where they
  come from (store, folder, sent by a node). The add-on that is not a profile's own copy shows as "default"
  instead of "installed". Runs of 1.0.0 keep showing the profile name they were recorded with.
- **StarBreaker with its version:** everywhere the UI shows StarBreaker it reads version+commit, as packshot's own
  version does (`0.3.2-ps.5+8b5ae08a`); runs record the version next to the commit (older runs show the commit only).
- **Node details:** the Nodes view's node tile has one row "Components" (packshot, StarBreaker, Blender) instead of the
  rows "App" and "Blender"; the add-on's hash is no longer shown there (the state check still compares it).
- **Cluster:** tested across real machines: one Windows and one Linux node rendered the full catalog, 6,682 of 6,734
  items in 3.5 minutes (the rest are items the game data has no model for).

## Install

As for [1.0.0](v1.0.0.md): download the bundle for your OS, run `setup.cmd` / `bash setup.sh`, then `check` and `run`.
Every node of a cluster needs the same packshot build: update all of them. The bundles carry StarBreaker 0.3.2-ps.5
and Blender 5.2.3 as before. Check the downloads against `SHA256SUMS`.

## Known limits

- The Windows bundle's `setup.cmd` has not been run on a second machine yet; please report what breaks.
- Nodes run Python they receive (`render.py`, profiles); share a cluster only with machines and people you trust.
